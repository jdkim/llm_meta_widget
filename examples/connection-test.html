llm_meta_widget — connection test

Checks, in order, everything the widget needs from the hub, then mounts the widget itself with one hub-registered tool pre-selected. That last part matters: a pre-selected tool makes every chat turn carry tool_ids, which is the path that fails if the hub rejects anonymous tool lookups.

  1. 1. Models — GET /api/llms (CORS + anonymous access)
  2. 2. MCP servers — GET /api/mcp_servers
  3. 3. Tools of the target server
  4. 4. Widget mounted with a pre-selected tool
Running…

If all four pass, open the panel at the bottom right and ask it to use the tool. A reply that uses the tool proves the whole chain; an error mentioning Token is missing would mean the hub still rejects anonymous tool lookups.
